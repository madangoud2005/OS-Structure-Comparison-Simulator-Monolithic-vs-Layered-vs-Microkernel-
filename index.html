OS Architecture Theory & Deep-Dive

Comparative Case Studies

1. Monolithic Kernel Architecture

Linux, FreeBSD, MS-DOS

In a monolithic operating system, the entire operating system executes within supervisor mode (Ring 0). Virtual memory, file systems, device drivers, process schedulers, and network stacks share a single unified address space.

✓ Maximum throughput (direct in-kernel C function calls) ✓ Only 2 privilege switches per syscall ✗ Zero internal fault isolation (driver crash = Kernel Panic) ✗ Enormous attack surface (>30M lines of code in Ring 0)

2. Layered Operating System

Dijkstra's THE System (1968), Venus

A layered architecture structures the OS into strict concentric tiers L0 to Layer N. Each layer encapsulates its implementation details and may only invoke services provided by the immediately lower layer Layer N-1.

✓ Clean formal verification and modular debugging ✓ Strict privilege encapsulation stops lower corruption ✗ Cascading stack overhead traversing every intermediate layer ✗ Hard to design without circular dependencies

3. Microkernel Architecture

MINIX 3, QNX Neutrino, seL4, Mach

Microkernels strip down Ring 0 to the absolute bare minimum: capability-based IPC, basic thread scheduling, and hardware interrupt mapping (<10k lines of code). Subsystems like filesystems and device drivers run as isolated user-mode daemons in Ring 3.

✓ Extraordinary reliability: user daemon crash cannot panic kernel ✓ Self-healing: Reincarnation server restarts dead drivers live ✗ Significant context switch and TLB invalidation penalties ✗ Memory copying overhead across isolated mailboxes

4. Hybrid Architectures

Windows NT, macOS XNU

Combines microkernel modularity with monolithic speed. Windows NT and macOS XNU run drivers and graphics in Ring 0 to avoid context switches while retaining message-passing abstractions.
